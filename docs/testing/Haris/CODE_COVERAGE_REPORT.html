Branch Coverage — Examples

Branch coverage checks whether both sides of every if/else in the code were tested. For every decision in the code, we tested what happens when it goes right and when it goes wrong.

Example 1 — User Login (94.73% branches ✅)

✅ Correct email & password → returns JWT token (200 OK)
✅ Wrong password → returns 401 Invalid credentials
✅ Unverified account → returns 403 Please verify email
✅ Missing fields → returns 400 Bad Request
✅ Password too long (>72 bytes) → returns 400 Bad Request

Example 2 — Admin Approve / Reject Campaign (86% branches ✅)

✅ Approve existing campaign → status set to active, email sent (200)
✅ Approve non-existing campaign → returns 404 Campaign not found
✅ Reject campaign with reason → status set to rejected (200)
✅ Reject campaign without reason → still works, no crash
✅ Owner has no email → email skipped, no crash

Example 3 — OTP Signup Flow (88.05% branches ✅)

✅ Send OTP code → 6-digit code dispatched to email
✅ Submit correct OTP → returns verification proof token
✅ Submit wrong OTP → returns 400 Incorrect code
✅ 5 wrong attempts → returns 429 Too many attempts
✅ OTP expired → returns 400 Code expired
✅ Complete signup with valid proof → account created (201)

Example 4 — JWT Auth Middleware (100% branches ✅)

✅ Valid token → request passes through to route handler
✅ Missing Authorization header → returns 401
✅ Expired token → returns 401 Token expired
✅ Password changed (auth_version mismatch) → returns 401 Session expired
✅ Donor accessing admin route → returns 403 Forbidden

Example 5 — Payment Settlement Service (83.33% branches ✅)

✅ Valid payment captured → donation status updated to completed
✅ Payment already processed → returns already_completed (idempotent)
✅ Unknown order ID → returns missing status
✅ Wrong donor attempting payment → returns forbidden
✅ Database error → throws error, transaction rolled back
